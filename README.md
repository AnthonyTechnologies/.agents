# .agents

This repository is for sharing and archiving configuration files, guidance, and best practices for agents using the
AGENTS.md standard. This repository is intended to be cloned or referenced across projects so teams can reuse a
consistent set of agent guidelines and conventions.

## Purpose and Scope

- Centralize agent configuration and guidance to facilitate maintenance and evolution in one place.
- Encourage consistent behaviors across projects (e.g., agent standards, language paradigms, and repeatable task workflows).
- Serve as a lightweight reference for new contributors who use AI coding agents for development.

## Design Principles

The design principles of this repository are based on the [AGENTS.md](https://www.agents.md) standard,
[Skills](https://agentskills.io) standard, and 
[AI coding agent concepts](https://www.humanlayer.dev/blog/advanced-context-engineering) outlined by the HumanLayer team
(presented by Dexter Horthy).

The `AGENTS.md` standard is designed to ensure safe, predictable agent-human collaboration, prevent context exhaustion,
and support long-term project stability.

The `Skills` standard provides a manageable implementation for toolsets and context for agents to execute tasks
effectively.

The agent concepts outlined by the HumanLayer team discuss context window management, human alignment, and the
importance of predictability. 

## Repository Structure

### Contents

- `artifacts/` — Long-term storage for persistent files generated by agents, such as reports.
- `intermediates/` — Temporary storage for ephemeral files generated by agents during tasks.
- `skills/` — Skills which contain directives and guidelines tailored for individual AI agents and languages.
- `AGENTS.md` — Project guidelines agents should follow when executing tasks.
- `LICENSE` — License for this repository.
- `README.md` — Primary documentation (this file) for this repository.

### AGENTS.md

The `AGENTS.md` is a project's primary configuration file for all agents as descibed on
<[https://www.agents.md](https://www.agents.md)>. The `AGENTS.md` in this repository details best practices and 
guidelines for executing tasks effectively. Additionally, instructs loading additional context dynamically through
skills.  

#### Sections

- **Core Mandates**: Establishes safety, predictability, and human alignment rules to prevent destructive actions and secure the codebase's long-term integrity.
- **Resource Management**: Organizes the workspace by separating ephemeral files from long-term artifacts, reducing project clutter and context noise over time.
- **Context Window Management**: Employs output compaction and the checkpoint pattern to mitigate token drift, maintaining agent accuracy across extended workflows.
- **Skills**: Directs agents to load specialized contexts when working in specific domains or for particular tasks.

### Skills

Skills are on-demand instructions for agents stored in `skills/` as described on
<[https://agentskills.io](https://agentskills.io)>. The skills in this repository are for providing agents additional,
domain-specific context beyond what is in `AGENTS.md` to prevent context rot. 

- `agent-[name]`: Provide additional context for specific agents.
- `lanuage-[name]`: Provide additional context for programming languages.

## Repository Installation

**Option A** (recommended): Add this repository as a Git submodule. Run the following command in the root of the project:
    
```bash
git submodule add https://github.com/AnthonyTechnologies/.agents.git .agents
```
  
**Option B**: Copy this submodule into the target project.

**Option C**: Keep this repository separate and reference it during tasks; ensure the agent has access to the `AGENTS.md` file and related materials.

### Setup

1. Pull a copy of this repository locally, from the previous options.


2. Either configure the agent to reference the `./.agents/AGENTS.md` or point the project root's agent README (e.g. `AGENTS.md`, `CLAUDE.md`) to the submodule `AGENTS.md`.
   * `AGENTS.md`: `[More AGENTS Directives](./.agents/AGENTS.md)`.
   * `CLAUDE.md`: `@./.agents/AGENTS.md`.


3. If using Claude, its project configurations are located in the `.cluade/` directory of the project root. There are two ways to manage this:
   * **Global**: Skills can be copied into the global claude configurations, typically in the `~/.cluade/` directory.
   * **Project**: A "symbolic link" can be used to redirect `.cluade/` to `.agents/` directory. However, this approach may not be supported by all systems or configurations. Also, it is suggested to git ignore the `.cluade/` directory to avoid conflicts in git.

**Linux & macOS**
```bash
ln -s .agents .cluade 
```

**Windows**:
```cmd
mklink /D .cluade .agents
```

## Tips

The core guidance resides in `AGENTS.md`. Apply the following practical tips day‑to‑day:
- **Clean Workspace**: Use `intermediates/` for scratch files and `artifacts/` for long-term reports to maintain organization and avoid token drift.
- **Clear Biases**: Periodically delete or move `intermediates/` and `artifacts/` to avoid biased or unintended results.
- **Resource Management**: Configure the agent to filter or extract output for long-running processes (e.g., builds, lints) to avoid flooding the context window.
- **Testing Taxonomy**: Distinguish between "Temporary Testing" (ephemeral verifications, deleted after validation) and "Permanent Testing" (robust project tests for edge cases).
- **Checkpoints**: Ensure the agent periodically summarizes its findings when executing tasks that span multiple steps or tool calls.
